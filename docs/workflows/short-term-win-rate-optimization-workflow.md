## 0. 目标函数与核心理念

优化目标是**期望值**，不是胜率：

```
E = p × avg_win − (1−p) × avg_loss   （再乘以出手次数）
```

短线是负和游戏（印花税+佣金+滑点 ≈ 每笔来回 0.1~0.15%），edge 薄，本工作流只做三件"免费胜率"的事：

1. **不做坏日子** —— 情绪相位闸门（D1）
2. **不选坏股票** —— 数据完整性分类 + 校准概率展示（D2/D4）
3. **不出坏场** —— 战法归因 + 纪律执行率（D3/D5）

证据基线（S047 证据报告，2026-01-05~08-10，n=5267）：

| 口径 | 次日平均 | 胜率 |
|---|---|---|
| 全部候选 | +2.17% | 61.3% |
| live 段 | +1.46% | 56.8% |
| gene_score 55-60 档 | +3.96% | **76.8%**（n=69） |
| 溢价率因子最高档 | +5.37% | **82.3%** |

后续一切设计以此为基线；任何新功能必须证明能改善该基线的某个切面，否则不做。

## 1. 流水线总览

```
盘后 T 日                盘前 T+1                 盘中 T+1              盘后 T+1
─────────────           ─────────────            ─────────────         ─────────────
数据/情绪结算            闸门 → 选股               入场确认 → 盯盘        结算 → 反馈
                                                                        
STI 五阶段 ─┐            ① weather 闸门           ⑤ 竞价再确认          ⑦ 用户结算录入
weather 四态─┼→ 校准层 → ② 漏斗 R1-R3            （auction_screener）   ↓
赚钱效应 N2 ─┘   ↑        ③ 完整性分类            ⑥ 纪律提醒            纪律执行率（D5）
                 │        （D2: missing/          （止损价线推送）       ↓
分桶 hit 表 ─────┘         no_history 标记）       炸板预警              归因表累积（D3）
（S041 滚动回测）          ④ 校准概率展示                                ↓
                           （D4: P(红盘)+n）                            tear sheet（N5）
```

七个环节：数据 → 校准 → 闸门 → 选股 → 入场确认 → 出场纪律 → 结算反馈。当前系统的薄弱点集中在**闸门（只是阈值微调）**、**校准展示（分数非概率）**、**结算反馈（只记账不归因）**三处——即本工作流的施工面。

## 3. 实施阶段（W1-W6）

> 依赖关系：W1 是全部前置；W2/W3 可并行；W4 依赖 W1 证据表；W5 依赖 W3 归因 + 结算样本；W6 独立。
> 每阶段拆独立 spec（medium 级），工单先落 `.scratch/winrate-workflow/issues/NN-*.md`。

### W1 证据层（不改生产，纯脚本）

- **输入**：`.scratch/s047-gene-calibration/scatter.json`、`sti_timeline`（含 phase 历史）、weather 历史
- **动作**：
  1. phase × 次日收益证据脚本：weather 四态各档的候选次日 avg/hit（D1 闸门强度定参依据）
  2. 因子零值归因调查：868 条 live 全零行按 `no_history`（首板/新股，无历史输入）vs `data_missing`（取数失败/窗口不足）分类计数（D2 实施依据）
- **产出**：`.scratch/winrate-workflow/evidence/` 下两份证据表 + 结论文档
- **验收**：数字脚本可复现；phase 各档 n≥30 才下结论，不足则合并相邻档并标注
- **预估**：small（纯研究脚本）

### W2 闸门层（D1 + D2b）

- **输入**：W1 phase 证据表、`sentiment_weather` 现有口径
- **动作**：
  1. weather phase 接入漏斗**行为级**闸门：暴风雨 → 候选池收窄/清空（保留低吸类，具体档位按 W1 证据定）；阴天 → 限首板/炸板回封类；晴天全开。闸门是系统行为（不出候选），非建议文案，规避方向词合规问题
  2. 简报显著展示闸门状态 + 触发维度（哪几个 STI 维度拉响）
  3. `data_missing` 行：保留在列表（D2b 裁决：暂留观察），打 missing chip + 诊断卡计数；`no_history` 打"首板"标记
- **产出**：funnel 闸门字段（gate_state/gate_reason/allowed_strategies）+ 前端呈现
- **验收**：软闸门先行——被闸门压制的候选标"已压制"而非直接消失，证据确认后再切硬闸门；闸门状态可回放复现（AC5 口径）
- **预估**：medium（跨层）

### W3 归因层（D3a + D3b）

- **输入**：`strategies/strategy_backtest.py`、`winrate_records`
- **动作**：
  1. trades 补 date/code/name 三字段（S049 战法对比表前置件）
  2. 归因表：每战法输出 hit / 平均盈利 / 平均亏损 / 盈亏比 / 期望值 / 样本量，按入场日 **weather 四态**分层（与 D1 闸门同口径，全链路一套词汇）
  3. 回测 vs 实盘并排：回测期望 X% vs 结算实际 Y%，差值 = 滑点 + 纪律损耗
- **产出**：归因端点 + S049 战法对比表数据源
- **验收**：归因数字与 scatter 重算一致；每格 n<30 标注"样本不足"
- **预估**：medium

### W4 展示层（D4a/b/c，信息设计师主导）

- **输入**：W1 分桶 hit 表、S041 回测定时任务、scikit-learn（已在 requirements）
- **动作**：
  1. gene_score 保留为内部排序字段；前端展示换"校准后次日红盘概率 + 样本量 n"，映射用 `IsotonicRegression` 或分桶直映（n<30 的档与相邻档合并后标定）
  2. 校准表挂 S041 定时回测滚动重算，版本号 + 生效日期可查
  3. 展示位：漏斗矩阵行、个股详情、盘前简报；统一挂风险注记
- **验收**：60+ 档必须诚实显示回落后的概率（当前证据 67.6%, n=37），不得呈现"分越高越好"暗示；校准表重算前后端一致
- **预估**：medium

### W5 反馈层（D5，P2，双门槛启用）

- **启用门槛**：winrate_records ≥30 笔 且 W3 归因表上线
- **动作**：
  1. 纪律执行率：每笔结算用 mootdx K 线（不碰东财）回放入场→出场价格路径，对照 STRATEGY_REGISTRY 理论出场（止损/止盈/max_hold_days），输出执行率 % + 损失归因（破止损未走多亏 X / 提前跑路少赚 Y / 超期暴露 Z）
  2. half-Kelly 仓位建议：`f = 0.5 × (b·p − q) / b`，p/b 取 W3 归因表"战法 × weather"格，乘 weather 系数（暴风雨→0，与 W2 一致），**接入 S042 统一持仓建议引擎**，不新建引擎
- **验收**：执行率数字可手工抽 3 笔复核；仓位建议与 S042 既有输出不冲突
- **预估**：medium

### W6 模型治理（D6）

- **动作**：
  1. ML 栈（`backend/predict/`）冻结：W2-W4 落地且 W3 归因表每"战法 × weather"格 n≥30 前，不新增模型工作
  2. walk-forward 协议落 `docs/workflows/model-walk-forward-protocol.md`：时序切分不 shuffle、embargo 间隔、仅样本外评估、**必须跑赢 S047 分桶基线**方有存在价值
  3. 协议作为未来模型类 spec 的流程门写入 AGENTS.md 补充条款
- **预估**：small（纯文档 + 冻结声明）

| **W5'** | **回归变体影子**（D7b）：估值分位池 + 触发器（风格轮动信号/资金流转正/基本面拐点）影子池，验证 20-60 日回归收益 | | W1 之后，与动量放宽**串行**不并行 |

串行纪律：W0 对照数据出来之前，不启动任何新管道建设；动量放宽与回归变体影子验证不同时上，一次只验证一个假设。

### 10.3 edge 族与出场规则映射

| edge 族 | "低买"定义 | "高卖"定义 | 止损 | 用户注意力消耗 |
|---|---|---|---|---|
| 动量溢价 | 强势确认早期（竞价/盘中确认入场） | 移动止盈（回撤离场）+ 时间止损 | 硬止损（战法参数） | 高（盯盘/竞价） |
| 事件溢价 | 催化剂落地初期 | 事件被充分定价（影子校准退出点） | 事件证伪即走 | 中 |
| 均值回归 | 估值低分位 + 触发器确认 | 目标分位分批卖出（卖在强势） | 基本面恶化（anomaly 信号）/ 时间止损 | 低（周度检查） |

动量吃盯盘时间、回归吃耐心，两者注意力互补——用户可随时盯盘是动量侧的真实优势；但约定：**盯盘是执行规则的场所，不是产生新决策的场所**（防感觉交易回潮）。

### 12.2 W-C 盯盘教练（阶段定义）

**目标**：把 A 股交易日固定的高价值时刻表内置进助手，到点教、到点提醒；用户照规则决策，不靠盘感。会盯盘不是反应快，是知道每个时刻该看什么、怎么判断、做什么。

**时刻表（教练内容种子）**：

| 时刻 | 环节 | 看什么 | 怎么判断 | 教学点 |
|---|---|---|---|---|
| 9:15-9:20 | 假竞价 | 只看不动 | 挂单可撤，大单常是诱饵 | 别被虚假高开骗 |
| 9:20-9:25 | 真竞价 | 竞价价/量/未撤单 | 9:20 后不可撤才是真金白银 | 竞价的钱最诚实 |
| 9:25 | 竞价确认 | 候选清单逐只对照战法入场区间 | 高开/竞价量达标才算条件成立，超区间划掉 | 全天第一个决策点 |
| 9:30-10:00 | 封板主战场 | 首封时间/封单额/炸板数 | 封板强度≥阈值→战法条件点亮；炸板→等回封 | 9:40 前首封=强 |
| 10:00-10:30 | 分歧窗口 | 龙头扛住否、跟风掉队否 | 分歧不等于退潮，分歧期不加仓 | 看龙头不看杂毛 |
| 11:00-13:30 | 垃圾时间 | 原则上不新开仓 | 午间量能低、假信号率高 | 管住手主战场 |
| 14:00-14:30 | 回封窗口 | 炸板股回封否 | 回封+强度≥0.6→炸板回封战法点亮 | 回封=共识修复 |
| 14:30-14:50 | 止损执行窗 | 持仓 vs 战法止损线 | 破线未收回→按纪律执行 | T+1 不执行=明日裸奔 |
| 14:50-15:00 | 尾盘 | 急拉股辨别 | 偷袭（弱）vs 共识（强） | 偷袭板次日大概率挨打 |
| 收盘后 | 复盘三问 | 推了什么/中了多少/为什么漏了 | 填结算票根 | 复盘产出迭代数据 |

**MVP 范围（一期）**：时刻表页（当前环节高亮，复用 `trading_workflow.get_current_stage`）+ 候选条件状态清单（逐只报 `STRATEGY_REGISTRY` 条件达成度，如"连板接力入场条件 2/3 达成，缺：竞价量"）+ 教学点（默认开，D8c）+ 降级模式盘前选择。复用：`auction_screener`（竞价）、`bomb_alert_system`（炸板预警）。**二期**：推送通知（notification/ 既有 15+ 通道）+ 无响应自动降级检测。

**降级阶梯（D8d）**：

| 档 | 适用 | 系统行为 |
|---|---|---|
| A 全程盯盘（默认） | 有时间 | 完整时刻表推送 |
| B 关键节点（约10分钟/天） | 时间零碎 | 只推两次：9:20 最终可执行清单+预埋单建议；14:25 止损窗口提醒；盘中信号静默累积在页面 |
| C 完全缺席 | 全天没空 | 四条铁律：① 禁开新仓（信号标"今日未确认、收盘过期"，宁可错过）② 止损前置为条件单清单（盘前 9:15 前推：代码/止损价/数量/原因，用户在券商 App 挂单）③ 触及 max_hold_days 的持仓置顶提醒，未操作则次日开盘前再推 ④ 收盘后一次性复盘推送 |

**交易完整性定义**：每个持仓有出场路径（条件单或显式计划），每个信号有明确状态（已确认/过期/冻结）——完整性不等于每步亲自操作。下单动作永远由用户在券商完成，系统不接交易（红线）。

### 12.3 方向建议口径（弱合规，依 CLAUDE.md §1.1/§1.2 与 chat.SYSTEM_PROMPT）

系统定位私人投研助理（半自动化：系统给建议，用户最终决策）。可给方向性研判、买卖时机研判、明确操作建议。每条方向建议必须同时满足：

1. **数据+规则背书**：判断基于公开数据+既定规则可复算，禁臆造禁心算（§1.2 工程底线）；附产生该建议的数据与规则出处；
2. **样本量与置信度**：附 n 与 t 值（D7d 口径）；样本不足明示"参考价值低"；
3. **讲清多空两面**：风险两面都讲，附证伪条件（"何种情况下此判断不成立"）；
4. **收益预期用三情景测算**（乐观/中性/悲观概率或分位区间），禁止确定性承诺（不得"必涨/必跌 X%"）；
5. **挂轻量风险提醒**：「历史统计特征，市场有风险，研究参考」；
6. 个股级分析按 `chat.ANALYSIS_FRAMEWORK` 五维组织（估值/资金面/财报质量/行业景气/事件催化与风险），结论先行。

禁止：无数据支撑的方向输出（主观断言/消息/纯情绪）。
说明："零方向结论词"不是本项目合规要求（过度从严的误读）。`limitup_strategy.py` 等遗留模块的"教育性展示，非行动建议"措辞是 S010 前旧口径——新模块（W-C 教练等）一律按本节弱合规口径，遗留措辞随后续迭代清理（不属本工作流范围，记录备查）。

### 12.4 教学目标与独立性指标

产品理念修订：**助手是教练，不是拐杖**——目标是用户脱离助手也能正确决策。

1. **每条方向建议都是例题**：数据 → 规则 → 结论 → 证伪条件，用户读推理过程不是读答案；
2. **教学点讲机制不讲动作**：讲"为什么这个时刻重要"，不只讲"现在该做什么"；
3. **独立性指标**（并入 W0 影子对照）：用户独立判断 vs 系统判断的一致率 + 用户独立判断的胜率；
4. **毕业轨迹**：一致率上升 → 用户独立判断胜率连续 4 周稳定跑赢基线 → 毕业，助手退化为数据看板+复盘工具（高价值时刻推送保留）。
