## 5. 对 plan 的实现期修正（基于 verify workflow dossier 漂移）

verify workflow（11 cluster read-only fact-check）揭示 plan 若干 stale/错误，实现期据实修正：

1. **A10 防封底线修正**：plan 写"从 market._sectors() 取"——dossier cluster 4 揭示 `_sectors()` 直接调用无缓存 + raw akshare `stock_fund_flow_industry` 不走 em_get/circuit_breaker。修正：sectors 从 `market.get_overview()["sectors"]` 取（5min 缓存），不在 fund_flow 内裸调 `_sectors()`。
2. **A9 历史日路径估值字段**：plan R4.1 说 pe_ttm/mcap_yi/pb 从 tencent_quote 取——dossier cluster 3 gotcha 1 揭示 tencent_quote 是**当日值**，历史日路径用 model.pe_ttm/pb/mcap_yi 会把今日值误当历史日值。修正：历史日路径 pe_ttm/pb/mcap_yi = None + missing（"当前估值非T-1，历史日路径无源"），不臆造；batch 当日路径才直接读 Quote 模型字段。
3. **C3 不用 FunnelLayers**：plan C3 说"用 FunnelLayers + SelectionPipeline"——dossier cluster 10 揭示 FunnelLayers 是 dead code（无生产 consumer）+ 与 SelectionPipeline 同渲染 FunnelLayerCard 会 double-render。修正：只用 SelectionPipeline（mirror Candidates.tsx precedent），不用 FunnelLayers。
4. **API 方法名**：plan/spec 说 `getFunnelLayers`——dossier cluster 10 揭示实际方法名是 `layers`（spec.md:138 stale）。修正：用 `candidatesApi.runFunnel`（选股池 Tab）。
5. **tencent_quote 返回 dict**：dossier cluster 5 揭示 tencent_quote 返回 `dict[str,dict]`（不是 list）+ raw key 是 `mcap_yi/limit_up/limit_down/change_amt`（不是 Quote model 的 market_cap/limit_up_price/change_amount）。实现用 Quote 模型字段（quote_from_tencent 已映射）。
6. **DiagnosisCard 子对象用 dict 不用 GeneScore 类型**：dossier cluster 1 gotcha 2 揭示用 Optional[GeneScore] 需跨模块 import + `_collect` 的 model_dump(mode='json') 对 raw GeneScore 对象会崩 + 静默丢全部 final_candidates。修正：3 子对象用 Optional[dict]，diagnosis.py 用 gene_obj.model_dump(mode='json')（hasattr 防御非 pydantic）。

## 6. 已知限制与诚实标注（§44）

1. **spec 矛盾：zt pool 无 hs**：spec §3.1 R5.2 说 weak_turn_strong 从 `card.pool_item` 读 `hs`（当日换手率），但 dossier cluster 5 确认 em_zt_topic_pool 涨停池原始 dict **没有 hs 键**。保守处理：不改 L811 的 hs 取数路径（避免改 pre_market_workflow 既有行为破坏 s081），故 weak_turn_strong 的 f5（vol_ratio_1d）在 card 非空时 hs=None 不命中，最多 4/5（confidence 0.7）。pattern_reversal 的 f4 从 amount_yi/prev_amount_yi 补活可 5/5。建议后续从 `indicators.turnover_pct` 补 hs（需评估对 pre_market_workflow 既有行为的影响）。
2. **`_sectors()` 无 T-1**：`market._sectors()` 调 `akshare.stock_fund_flow_industry(symbol="即时")`，无 date 参数，无法显式取 T-1。spec "盘前取昨日 _sectors() 返回值" 依赖 akshare 盘前行为（返回前一日数据），不可从代码控制/不可离线验证。盘前实际可能 3 字段 None。`fetch_sector_flow`（个股级）已对 date<today 返 None 防未来函数，行业级无此防护——建议后续 live 验证盘前 _sectors 行为。
3. **`individual_info` per-code raw akshare（已修，review HIGH）**：初版 fund_flow 的行业匹配 per-code 调 `astock.individual_info(c)`（raw akshare 东财无 em_get/circuit_breaker，80 候选=80 burst 请求，§1.2 防封底线违反）。adversarial review HIGH 抓出后修复：改用 zt pool 的 `hybk` 字段（em_get-backed，first_board_filter.fetch_zt_pool 链路）提取 `industry_map` 传入 fund_flow，删 individual_info 调用。覆盖不全（只昨日涨停的票有 hybk）的标 missing 降级，不臆造。
4. **`_A_SHARE_HOLIDAYS` 仅 2026 日期**（dossier cluster 8 gotcha 3）：`vr_paths._A_SHARE_HOLIDAYS` 只列 2026 法定节假日，历史回测 T-1（2025 等非 2026 年）节假日会被误判为交易日（周末回溯仍安全）。S084 主用盘前（今日），不影响；历史回测 edge case 需注意。
5. **dragon_head registered-but-unmatched**（dossier cluster 7 gotcha 1）：STRATEGY_REGISTRY 第 9 个既有战法 `dragon_head`（S062 T3）在 match_strategies 无分支，silently falls through。S084 B2 未给它加分支（plan 未要求，保持现状）。如需激活需单独 spec。
6. **pattern_reversal entry_price 用 pool_item.p**（既有 S081 行为，L957）：触发价 = _round_to_tick_size(pool_item.p + 0.01)。pool_item.p 是涨停价（来自 em_zt_topic_pool），非 K线 high（原 S081 重构删了 kline 取数）。这是 S081 既有设计，S084 未改。
7. **weak_turn_strong f4 年份硬编码**（dossier cluster 7 gotcha 5）：L868 `last_lock_time >= f"2026-01-01T{TH_LOCK}"` 字符串比较带字面年份。S084 未改（B2 保留 fallback，card 非空时 last_lock_time 来自 card.derived 的 ISO8601 字符串，比较仍工作但跨年边界脆弱）。建议后续修。
