### 1.2 架构冲突

当前单漏斗 R1→R2→R3 服务 9 个战法，但：

## 2. 设计目标

1. **提高期望收益（赚钱）**：期望 = 胜率 x 平均盈利 - (1-胜率) x 平均亏损。不只追求胜率——高胜率低盈亏比可能负期望。目标：胜率 >= 75% 且盈亏比 >= 1.5 且期望 >= +2%/笔
2. **策略分流**：每个战法独立漏斗 + 独立因子权重 + 独立质量标准
3. **天气硬开关**：不同天气跑不同策略组，不适配的不跑
4. **板块热度过滤**：剔除冷门板块一日游涨停
5. **日历因子**：PositionAdvisor 按日历调仓（周五×0.7，节前×0.5）
6. **前端统一风格**：盘前/盘中/盘后三页面统一设计，因子可点击跳详情
7. **扩展预留**：注册表式架构，新战法追加声明即可

## 3. 架构设计

### 3.1 总体流程

```
天气/STI（硬开关）
  │
  ├─ 晴天 → consecutive_relay, dragon_head, platform_breakout (+ low_absorption 备选)
  ├─ 阴天 → first_plate, break_reseal, end_of_day_sneak (+ low_absorption 备选)
  ├─ 极端反弹 → reverse_package, break_reseal, n_shape_counterattack
  ├─ 暴风雨 → 不开仓
  └─ 未知 → first_plate, consecutive_relay（保守）
        │
        ▼
  策略特定漏斗（按 weather 选择的策略组并行运行）
  │
  ├─ 涨停类(limitup)：gene_scores → 策略分排序 → 板块热度过滤 → 策略质量标准 → 候选
  └─ 非涨停类(market_scan)：热门板块 → 板块成分股 → 形态扫描 → 策略分排序 → 候选
        │
        ▼
  PositionAdvisor（日历因子 × 仓位建议）→ 最终推荐
```

### 3.2 策略注册表

```python
@dataclass
class StrategyFunnelConfig:
    code: str                                    # first_plate / consecutive_relay / ...
    name: str                                    # 首板挖掘 / 连板接力 / ...
    funnel_type: Literal["limitup", "market_scan"]
    factors: dict[str, float]                    # 策略特定因子权重
    weather_regimes: list[str]                  # 适配天气
    quality_standards: list[QualityCheck]        # 策略特定质量标准
    position_params: PositionParams              # stop_loss/take_profit/max_hold
    is_primary: bool                             # 天气匹配时是否主跑
    fallback: bool                              # 主跑无候选时是否尝试
```

新晋战法：在 `STRATEGY_FUNNEL_REGISTRY` 追加一条 `StrategyFunnelConfig`，自动被天气开关调度。不改动框架代码。

暴风雨逆势涨停子策略（storm_reversal）：
- funnel_type: limitup（复用 gene_scores 数据源，但只取暴风雨日的涨停股）
- factors: seal_rate x 0.60 + (100 - freq) x 0.40（暴风雨逆势涨停只看封板强度 + 新鲜度）
- weather_regimes: ["暴风雨"]
- position_params: stop_loss=-3%, take_profit=10%, max_hold=1
- quality_standards: 封板时间 <= 10:30（暴风雨天尾盘涨停不算逆势，可能只是恐慌后反弹）
- is_primary: True（暴风雨天唯一主跑策略）
- 仓位 x 0.3（环境极端）

## 4. 策略特定因子权重

> **重要**：以下权重公式为候选方案。最终权重由 Phase 0b 全样本回归（6537 样本）结果确定。
> 只有 95% CI 排除 0 的因子才进入策略分公式。不显著的因子用等权或权重 0。
> 候选公式的设计逻辑仍然有效，但数值权重待数据确认。

### 4.0 三套权重（不是九套）

9 个策略不需要 9 套独立权重——样本量不够支撑每个策略单独估参。改为 3 套：

| 权重集 | 适用策略 | 共享原因 | 样本量（Phase 0a 后） |
|---|---|---|---|
| 涨停类 | 首板/连板/炸板回封/尾盘偷袭 | 因子本质相同（封板率/连板率/频次），侧重不同但排序可共用 | ~5000+ |
| 非涨停类 | 低吸/反包/平台突破/龙头 | 因子体系不同（相对强度/均线/形态），但同属形态扫描类 | 待 Phase 2 有数据后估 |
| 暴风雨逆势 | storm_reversal | 独立场景，样本极少 | ~50-200 |

各策略仍有独立的**质量标准（§7）和入场条件**——只是因子排序权重共用。
排序后按战法标签分组展示，不是排序前用不同权重。

### 4.1 涨停类候选权重（首板/连板/炸板回封/尾盘偷袭 共用）

> **grill 2026-08-16（Q14-Q15）改写**：Phase 0b 回归结果显示原权重体系失效——
> seal_rate r=+0.046 不显著（spec §1.1 的 r=+0.18 未在 1587 样本复现），
> red_rate/freq_score/total_score 方向不稳定（122 天无信号 vs 27 天弱正相关，无法定方向）。
> ~~**唯一强信号**：rebound_rate r=+0.179（p=6e-13, CI=[0.131, 0.227]）——升主因子。~~
> **二轮验证收回（2026-08-16）**：rebound_rate 是日级市场变量——`limitup_screener/service.py:_compute_rebound_rate`
> 算的是 T 日炸板池次日回封率，天然市场级，广播给当日每只票（24 天中 75% 交易日全市场单值，
> 日均 distinct=1.25）。日内/日间分解：pooled r=+0.179 → within-day r=-0.010（横截面零选股力），
> between-day r=+0.587（行情制度效应），方差 78.8% 在日间。day-cluster bootstrap（按日整日重抽，
> B=800）：pooled r CI=[-0.019,+0.296] 含 0，within CI=[-0.133,+0.048] 含 0——p=6e-13 是 IID 假设假象，
> 有效样本实为 24 天不是 1587 条。**全部 6 个因子 within-day r≈0 且 bootstrap CI 全含 0**
> （premium +0.040 / red +0.027 / seal +0.010 / rebound -0.010 / freq +0.027 / total +0.024），
> eastmoney_live 24 天里没有任何已验证的横截面选股因子。
> §4.4"反向因子"理论删除不变（大样本下 freq/red 不是负相关，反转无意义）。

```
score = rebound_rate x W1 + seal_rate x W2 + premium x W3 + freq x W4 + zt_count_golden x W5
```

设计逻辑（Phase 0b 回归后）：
- rebound_rate：pooled r=+0.179 已证伪为日级伪信号（见上方收回说明），**降回普通因子**，等权 placeholder 保留观察；
  另注意其为市场级变量，横截面排序中不产生区分度，实际近似常数项
- seal_rate：within-day r=+0.010（CI 含 0），无已验证信号，等权 placeholder
- premium/red/freq：within-day r≈0（CI 含 0），等权 placeholder，待 60 天 eastmoney_live 积累后重判
- zt_count_golden：黄金区[2,5]=1.0, [6,8]=0.5, 9+=0.1, 1=0.0（未回归，保留）

候选初始值（等权 placeholder，Phase 0d 后热替换）：
```
W1 = W2 = W3 = W4 = W5 = 0.20
```

其余等权或权重 0。当前 6 因子 within-day CI 全含 0，故等权是唯一有数据支撑的起点。

### 4.2 非涨停类候选权重（低吸/反包/平台突破/龙头 共用）

```
score = relative_strength x W1 + ma_bullish x W2 + volume_signal x W3 + sector_strength x W4
```

因子定义：
- relative_strength：个股 5 日涨幅 - 板块 5 日涨幅
- ma_bullish：MA5 > MA10 > MA20 = 1.0，否则按偏离度评分
- volume_signal：量比 > 2 = 1.0（突破放量）/ 资金净流入 = 1.0（低吸）/ 成交额 > 15亿 = 1.0（反包）——按战法上下文选
- sector_strength：板块涨幅排名分（top-5 = 1.0, top-20 = 0.5, 其他 = 0.2）

候选初始值（等权起步）：
```
W1 = W2 = W3 = W4 = 0.25
```

Phase 2 有数据后单独估参。

### 4.3 暴风雨逆势候选权重（storm_reversal 独用）

```
score = rebound_rate x 0.50 + seal_rate x 0.50
```

> **grill 2026-08-16 改写（二轮验证后修订）**：原 `seal_rate x 0.60 + (100 - freq) x 0.40` 的 freq 反向已删除（§4.4）。
> 一轮结论"rebound_rate 唯一强信号"已证伪（日级市场变量，见 §4.1 收回说明）——但等权公式本身不受影响：
> 两个因子都没有已验证的横截面信号，等权仍是诚实起点。暴风雨逆势涨停看封板强度 + 炸板后回封率。
> 样本极少，不做回归，固定权重；rebound_rate 的市场级属性意味着此公式实际退化为"当日回封率 x 0.5 + 个股封板率 x 0.5"，
> 区分度全靠 seal_rate。

### 4.4 ~~反向因子说明~~（已删除，grill 2026-08-16）

> **grill 2026-08-16（Q14-Q15）删除**：原"premium/freq 用 (100-value) 反转"理论基于 spec §1.1 的 74 样本 r=-0.26。
> Phase 0b 回归（3760+1587 样本）显示 freq 在 122 天大样本无信号（r≈0），27 天小样本弱正相关（r=+0.073），
> 不是负相关。反转因子无意义，删除。(100-premium) / (100-freq) 的反向操作全部去掉，因子值直接正向用。

## 5. 板块热度——时序周期分析

### 5.1 问题定义

板块不是单日现象，是时序周期：

```
Day 1: 1-2 只涨停 → 板块启动（可能是明天的热点起点）
Day 2: 3-5 只涨停 → 板块发酵（资金涌入，跟风股出现）
Day 3: 5-10+ 只涨停 → 板块高潮（最热，但退潮风险最高）
Day 4: 涨停减少、炸板增多 → 板块退潮（追入即套）
```

单日"板块涨停数 >= 2"过滤有两个致命缺陷：
1. **误杀启动**：Day 1 的 1 只涨停被过滤，但那可能是板块最值得参与的一天
2. **不识退潮**：Day 4 的 3 只涨停通过了 >= 2 阈值，但板块正在退潮，追入即套

正确做法：不看单日绝对数，看**3 日时序动量**判断板块在周期中的位置。

### 5.2 板块周期阶段分类

对每个板块，用 T-1/T-2/T-3 的涨停股数 + 当日涨停股数计算：

```
count_today = 当日该板块涨停股数
count_avg_3d = (T-1 + T-2 + T-3) / 3 的该板块涨停股数均值
momentum = count_today - count_avg_3d
```

阶段判定：

| 阶段 | 条件 | 含义 | 操作 |
|---|---|---|---|
| 启动 | count_avg_3d <= 1 且 count_today >= 1 | 板块从冷转热，可能是明天热点 | 保留，标注"启动期" |
| 发酵 | count_today > count_avg_3d 且 count_avg_3d >= 1 | 板块在升温，资金涌入 | 保留，标注"发酵期" |
| 高潮 | count_today >= 5 且 count_today >= count_avg_3d | 板块最热，但退潮风险最高 | 保留但标注"高潮期，注意退潮" |
| 退潮 | count_today < count_avg_3d 且 count_avg_3d >= 3 | 板块在降温，追入即套 | 标注"退潮期"，不过滤但用户自行判断 |
| 冷门 | count_avg_3d = 0 且 count_today <= 1 | 板块无持续性，可能一日游 | 标注"冷门" |
| 无历史 | T-1/T-2/T-3 数据缺失 | 新板块或数据不全 | 中性标注 |

> **task 119 边缘 case 修正（2026-08-16）**：`has_history=True` 但无子句命中（如 `today=0 + avg∈(0,3)`：不命中退潮 avg<3、不命中冷门 avg≠0）原 fallthrough 误返"无历史"——违反 spec（无历史=数据缺失，非"无子句命中"）。修正：`has_history=True` 无命中 → **退潮默认**（今日相对 3 日基线走弱/持平）。"无历史"专用 `has_history=False`。退潮子句 avg>=3（强退潮"追入即套"）不动；温和走弱走 fallthrough→退潮（modifier §5.4 已 label-only，无策略分影响）。

### 5.4.1 板块强度排名

不仅看周期阶段，还看板块间相对强度：

sector_strength = zt_count_today x 0.40 + zt_momentum x 0.30 + fund_flow_direction x 0.30

- zt_count_today：当日涨停数
- zt_momentum = count_today - count_avg_3d
- fund_flow_direction：板块资金净流入方向（sector_flow 已有）

输出 TOP-10 板块强度排名。候选股板块排名越高修饰越高：TOP-3 x1.05，4-10 x1.0，11+ x0.95。

### 5.4.2 板块停留天数

追踪板块在当前阶段停留的天数。发酵期 Day 1-2 值得跟进，Day 3-5 接近高潮，Day 6+ 可能过热。
停留天数作为前端展示信息。

### 5.4.3 跨板块轮动检测

对比 T 日 vs T-1 日板块涨停数排名变化。上升 >= 5 位 = 启动候选，下降 >= 5 位 = 退潮。
标注轮动信号 A->B。输出到盘前"板块轮动"面板。

### 5.4.4 板块广度

sector_breadth = 板块内涨幅>0 的股票数 / 板块总股票数。
涨停 2 + 广度 80% = 健康板块普涨；涨停 2 + 广度 20% = 个股行情无板块效应。
数据来源 industry_comparison 的 up_count/(up_count+down_count)。

### 5.5 非涨停类

非涨停类候选来自板块成分股扫描（§8 数据源）。板块阶段同样适用：
- 启动/发酵期板块 → 扫描优先（板块刚启动，候选质量高）
- 退潮期板块 → 跳过扫描（板块在退，找形态突破也是假突破）
- 冷门板块 → 跳过（无资金关注，突破无人接）

### 5.6 板块轮动追踪（增强，P2）

追踪板块在周期中的流转：
- 记录每个板块每日的 zt_count → 形成板块热力图（日 x 板块）
- 识别"接力轮动"：板块 A 退潮 → 板块 B 启动（资金从一个板块流向另一个）
- 输出到盘后页面的"板块轮动"面板

当前只做 3 日时序，不做跨板块轮动追踪（P2 后续）。

```python
def calendar_factor(signal_date: str) -> tuple[float, str]:
```

### 6.2 节后红包确认策略

不空仓节前末日，但不全仓——留窗口等节后确认：

## 9. 游资席位分析

### 9.1 问题定义

当前系统用 `fetch_dt_hot_money_relay` 聚合龙虎榜游资净额，但不区分席位类型。实际市场中游资席位分三类：

| 席位类型 | 行为特征 | 对 T+1 的含义 |
|---|---|---|
| **一日游** | T 买入、T+1 卖出，隔日套利 | 他们在场 = T+1 有抛压 = **风险** |
| **接力型** | 持仓 2-5 日，板块内轮动 | 他们在场 = T+1 有支撑 = **正面** |
| **机构** | 持仓较长，调仓行为 | 混合信号，需结合方向判断 |

### 9.2 与回测结论的关系

回测发现"游资净流出组胜率 83.3%"——这是**聚合净额**的结论。席位类型是**更细维度**：一只票可能聚合净流出，但流出的全是一日游游资（他们本就要卖），反而正常；如果聚合净流入但流入的是一日游游资（明天要卖），才是隐患。两个维度互补，不矛盾。

### 9.3 席位画像构建

数据源：`eastmoney_datacenter` 的 `RPT_BILLBOARD_DAILYDETAILSBUY/SELL`（已有接口）。

对每个 `OPERATEDEPT_NAME`，基于 60 日历史龙虎榜数据计算：
- `next_day_sell_rate`：T 日买入后 T+1 日在卖方榜出现的比例
- `appearance_count`：上榜总次数

分类阈值：
- `next_day_sell_rate >= 0.7` 且 `appearance_count >= 3` -> "一日游"
- `next_day_sell_rate <= 0.3` 且 `appearance_count >= 3` -> "接力型"
- 其他 -> "混合型"
- `appearance_count < 3` -> "样本不足"（不分类不标注）

画像缓存到 `backend/data/hot_money_seats.json`，每周盘后更新（周六批量拉 60 日龙虎榜，约 18 次 API 调用）。

周更为主 + 行为突变检测：
- 每日增量：拉最近 5 个交易日的龙虎榜数据（约 350 条，2 次 API 调用）
- 对每个席位：比较最近 5 日 next_day_sell_rate vs 60 日均值
- 偏差 > 30% → 标注"行为变化"，候选卡片提示"该席位近期行为与历史不一致"
- 不需要日更全量画像，只追踪增量变化

这样在市场 regime 突变时（如政策出台），系统能在 5 日内感知游资行为变化，不需要等周更。

### 9.3.1 预设席位画像（初始化定义）

部分游资席位在市场中有明确的已知行为标签，不需要等 60 日数据积累。系统内置预设画像，用市场反馈初始化，后续用实际数据修正：

### 9.4 策略分接入

新增因子 `hot_money_seat_risk`：

```
day_trip_ratio = 一日游席位净买入额 / 总净买入额
day_trip_ratio > 0.5 -> 策略分 x 0.7（高风险）
day_trip_ratio 0.2-0.5 -> 策略分 x 0.9（中风险）
```

适用：所有涨停类 + 反包战法。不适用于平台突破/低吸龙头。

- 不输出个体席位名（S018 R11：个体席位标签 alpha 已衰减，只用聚合分类）
- 画像数据存本地 JSON，不外传
- 前端只输出分类标签 + 聚合金额，不暴露具体营业部名称

## 10. 资讯雷达上下文层

### 10.1 定位

资讯雷达（`newsradar.py`，108 个 RSS 源 x 13 赛道）是**定性上下文层**，不是量化因子。它不参与策略分计算，而是在量化因子之上提供人机协作的研判信息，辅助用户做最终决策。

与因子全景表（`factor-catalog.md` 62 条量化因子）的关系：因子是"可计算、可回测"的硬指标，资讯雷达是"可参考、不可量化"的软信息。两者互补，不替代。

### 10.2 三层接入

**层 1：板块资讯热度（半量化，辅助板块热度过滤）**

当前板块热度只看"涨停股数"（section 5）。资讯雷达加一个交叉维度：

```
板块热度 = 涨停股数（硬信号） + 最近48h新闻条数（软信号）
涨停>=2 + 新闻多  = 板块真热（有基本面驱动）-> 保留
涨停>=2 + 新闻少  = 可能纯情绪炒作 -> 标注"情绪驱动，一日游风险"
涨停=1  + 新闻多  = 事件驱动（新闻催化）-> 标注"事件驱动"
涨停=1  + 新闻少  = 冷门 -> 标注"冷门板块"
```

新闻条数阈值：取最近 7 日各板块平均新闻条数，超过均值 * 1.5 = "多"，低于均值 * 0.5 = "少"。

**层 2：催化上下文（定性，辅助 R3 催化判断）**

当候选股有公告催化时，检查对应赛道是否有相关新闻：
- "业绩预增"公告 + 赛道"行业政策利好"新闻 -> 催化可信度高，标注"双催化"
- "风险提示"公告 + 赛道"监管收紧"新闻 -> 双重利空，标注"风险叠加"
- "业绩预增"公告 + 赛道无相关新闻 -> 单一催化，标注"个股催化"

匹配方式：公告类型关键词（预增/扭亏/重组/回购）x 新闻标题关键词（政策/补贴/需求/增长/监管/处罚/整顿）。

**层 3：风险雷达（定性，辅助风险标注）**

如果候选股所在赛道最近 48h 有负面新闻关键词命中（"整顿/处罚/违规/下降/亏损/减持/解禁/风险"），在候选卡片标注"赛道风险"。

不做 NLP 情感分析——只做关键词命中 + 人工确认。资讯是辅助，不是自动决策。

### 10.3 板块映射

资讯雷达 13 个赛道（AI/半导体/机器人/医药等）与东财行业分类（教育/电子/化工等）不是 1:1。需要一张映射表 `backend/data/sector_mapping.json`：

```json
{
  "AI / 大模型": ["计算机", "软件服务", "通信"],
  "半导体 / 芯片": ["电子", "半导体"],
  "生物医药 / 健康": ["医药", "医疗器械"],
  "汽车 / 新能源车": ["汽车", "新能源"],
  ...
}
```

一个雷达赛道可映射到多个东财行业。映射表手动维护，赛道增减时更新。

### 10.4 前端展示

候选卡片新增"资讯雷达"折叠区：
- 板块资讯热度标签（真热/情绪/事件/冷门）
- 最近 3 条相关新闻标题（点击跳转原文）
- 赛道风险标记（如有）

点击板块热度标签 -> 跳转资讯雷达子页（面包屑：首页 > 盘前 > 连板接力 > 板块资讯 > [板块名]）

### 10.5 数据需求与优先级

资讯源并存，优先 A（免费 akshare），B（LLM API）做补充：

| 数据 | 优先级 | 来源 | 实现方式 |
|---|---|---|---|
| 个股新闻 | **A 主力** | akshare stock_news_em() | 东财新闻接口，HTTP API，不走 RSS |
| 个股新闻 | B 补充 | LLM API（Kimi/OpenAI） | 用户配置的 AI 层，搜索 + 摘要 |
| 板块新闻 | A 主力 | RSS（newsradar.py） | 108 源，如 RSS 可达则用 |
| 板块新闻 | B 补充 | akshare stock_news_em() | 用个股新闻聚合到板块 |
| 资讯缓存 | 已有 | backend/.cache/radar.json | 7 日 TTL |
| 板块映射表 | **需构建** | backend/data/sector_mapping.json | 雷达赛道 -> 东财行业映射 |
| 公告-新闻匹配 | **需实现** | 关键词匹配（A）+ LLM 分类（B） | A 做粗筛，B 做精细分类 |

接入策略：
- stock_news_em() 作为个股新闻主源——已有接口（akshare_src.py），免费，HTTP API 不依赖 RSS
- RSS 作为板块新闻源——如果 RSS 不可达（缓存为空），降级到从个股新闻聚合
- LLM API 用于公告分类（利好/利空/风险提示）和新闻情感——替代关键词匹配，更准确
- LLM 调用走系统已有 chat 层（backend/chat.py），用户配置自己的 AI provider

### 10.6 不做

- 不做 NLP 情感分析引擎（自建）——用 LLM API 替代，不自建 NLP
- 不做新闻条数作为策略分因子（定性信息不进量化公式）
- 不做实时 RSS 拉取（盘前读缓存或 akshare 即可）

## 11. 前端设计

### 11.1 三页面统一风格 + 渐进式披露

盘前 / 盘中 / 盘后共享渐进式披露（L0-L3），避免信息过载：

```
L0 决策视图（默认，80% 时间用）：
  每只候选一行：[代码] [名称] [策略分] [一句话理由] [仓位建议] [风险标签]
  用户扫一眼就能决定买不买。不展开任何因子细节。
  例：003032 传智教育 策略分85 | 连板接力+封板强 | 仓位4.5% | 游资中风险

L1 摘要视图（点击候选行展开）：
  板块阶段 | 日历因子 | 游资风险标签 | 板块热度排名 | 策略分构成
  例：板块发酵期 | 日历正常 | 一日游占比35% | 板块TOP3 | 封板率40%+频次25%+...

L2 详情视图（点击"更多"展开）：
  完整因子分解 | 质量标准检查 | 资讯雷达 | 游资席位明细 | 板块广度
  所有因子值 + missing 标注 + 质量标准 pass/fail

L3 因子子页（点击单个因子超链接）：
  因子定义 + 计算公式 + 当前值 + 历史分布 + 相关性 r + 分位胜率
  面包屑：首页 > 盘前 > 连板接力 > 封板率
```

顶部导航条：天气状态 + 当前策略组 + 日历因子提示
策略分组：按天气激活的策略组分 tab，每 tab 显示该策略的候选列表
默认 L0 视图——不铺开所有信息，用户主动展开才看到更多。

### 11.1.1 问 AI（每页内置）

每个独立页面（盘前/盘中/盘后/因子详情）右下角固定一个"问 AI"按钮。点击展开输入框，用户输入问题后，系统自动附带当前页面上下文发送到 /api/chat（已有 chat 层，用户配置自己的 AI provider）。

上下文按页面类型自动组装：

| 页面 | 附带上下文 |
|---|---|
| 盘前 | 天气/STI + 策略组 + 候选列表(代码/名称/策略分/因子值) + 板块周期 + 日历因子 |
| 盘中 | 持仓(代码/仓位/盈亏) + 情绪分数/趋势 + 市场指数 + 日历提示 |
| 盘后 | 当日命中率 + 策略分 vs 实际收益 + 因子 beta + 衰减监控 |
| 因子详情 | 因子定义 + 当前值 + r/CI/p + 分位胜率 + 交互关系 |

上下文以 JSON 结构化传递，AI 可以引用具体数据回答。例如用户问"003032 值得买吗"，AI 能看到策略分 85、封板率 98、游资中风险、板块发酵期等完整上下文。

合规：AI 回答标注"AI 辅助分析，不构成投资建议"。

### 11.2 盘前页面（PreMarket）——全时段定义

盘前不是 25 分钟——从昨日 15:00 收盘到次日 9:30 开盘都是盘前。不同时段用户需求不同，页面状态自动切换：

| 时段 | 页面模式 | L0-L3 层级 | 用户在做什么 |
|---|---|---|---|
| 15:00-18:00 盘后复盘 | 候选生成 | L1 摘要 | 复盘今日 + 生成明日候选池 |
| 18:00-22:00 晚间分析 | 深度研究 | L2 详情 + L3 因子 | 研究因子细节、资讯雷达、游资席位 |
| 7:00-9:15 盘前确认 | 数据刷新 | L1 摘要 | 刷新数据、确认日历因子、最终筛选 |

## 12. 回归验证框架

每个策略分上线前必须通过回测验证：
1. 用 gene_scores.db + kline cache 对每个策略分做五分位胜率回测
2. 策略分 Q5（最高分）胜率必须 > Q1（最低分）——证明排序方向正确
3. 策略分整体胜率必须 > 基准（当前 73%）
4. 样本量 < 30 的策略标注"样本不足，待积累"


### 12.1 基准定义

策略胜率必须有参照系。73% 不是 alpha 本身——alpha = 策略胜率 - 基准胜率。

```
benchmark_A: 全涨停股次日红盘率（不加任何选股的默认表现）
benchmark_B: CSI300 次日上涨概率（不做涨停策略的机会成本）
alpha = strategy_win_rate - benchmark_A
```

如果 benchmark_A 已经是 70%（涨停股本身就大概率次日红），策略 alpha 只有 3pp——接近噪音。
如果 benchmark_A 是 55%，策略 alpha 是 18pp——有实际价值。

回测必须同时输出 benchmark_A 和 benchmark_B 的胜率作为对照。

benchmark_A 是判断策略是否有 alpha 的第一道关——Phase 0a 回填 6537 样本时必须同时计算。
如果 benchmark_A 接近策略胜率，策略选股能力为零，§4 因子设计无意义。
如果 benchmark_A 远低于策略胜率，alpha 存在，继续优化因子。

所有统计结果必须报告 95% 置信区间。只有 CI 下界 > 基准的因子/定律才标注显著。点估计不够——73% 胜率的 CI 可能是 [62%, 83%]，下界 62% 接近基准就没有 alpha。

Phase 0b 全样本回归输出格式：
```
factor_name: r=+0.XX, 95% CI=[+0.XX, +0.XX], p=0.XXX, n=6537
  -> CI 排除 0 -> 显著，进入策略分公式
  -> CI 包含 0 -> 不显著，等权或权重 0
```


## 13. 实现优先级

### 13.0 MVP 原则

18 节 spec 是终态，不是初始态。上线路径：先最简版本验证 alpha 存在，再逐步增加复杂度。

**Phase 0（验证 alpha）**：涨停股 × 最低策略分排序 × 板块热度过滤。不接日历/游资/资讯/组合风控。用真实交易（或 paper trading）验证胜率 > 60%。

**Phase 0 通过后**：每加一层复杂度（日历 → 游资 → 资讯 → 组合风控 → 执行模型），都要回测验证该层确实提升了胜率或期望收益。不提升的不加——复杂性是 alpha 的敌人。

**每层的 kill question**：如果去掉这层，胜率降多少？降 < 2pp 的层是"锦上添花"，降 > 5pp 的层是"核心 alpha"。spec 实现时优先核心层，锦上添花层后置。

| 天气取不到时硬开关失效 | "未知"档保守降级到首板+连板 |
| 前端改动大 | 三页面共享组件，逐页上线 |


### 14.1 alpha 来源假设

"低分=高胜率"的发现需要明确 alpha 来源，才能预判何时衰减。四种可能：

| 假设 | 含义 | 衰减条件 |
|---|---|---|
| A. 均值回归 | 罕见涨停=新事件=注意力集中 | 被更多人知道并利用后衰减 |
| B. 流动性溢价 | 低频次票更小盘更不流动=波动更大 | 不是 alpha，是风险补偿，不衰减 |
| C. 小样本噪音 | Q1 只有 14 个样本 | 样本积累后消失 |
| D. Wilson 下界压缩 | 低样本量被过度惩罚=评分 bug | 换评分方法后消失 |

上线后追踪：Q1 胜率是否随样本增加而下降（C 的特征）？低频次票是否系统性更小盘（B 的特征）？如果 C 或 D 成立，"翻转排序"不是利用 alpha 而是放大数据 bug——需要重新审视评分方法而非翻转方向。

Phase 0b 全样本回归将直接验证四个假设：
- A（均值回归）：低频次票 + 低连板率票 -> 次日收益是否更高？6537 样本上 r 的方向和大小。
- B（流动性溢价）：低频次票的 float_market_cap 是否系统性更小？回归 freq -> market_cap。
- C（小样本噪音）：74 样本的 r=-0.20 在 6537 样本上是否消失？
- D（Wilson 压缩）：低 zt_count 票的 wilson_adjusted 是否系统性低于 raw score？

Phase 0b 的结论决定权重方向。不跳过这步。

> **grill 2026-08-16 决议（Q9-Q15 + 二轮验证）见 Phase 0b/0c/0d 段落 + §4.1/4.3/4.4**：双轨并存 + 查询层分层 + kline_rebuild 仅验证 3 因子方向 + 独立 CLI 脚本 + verdict 降级（B→时间窗口效应待验证）+ ~~rebound_rate 升主因子~~（二轮验证证伪：日级市场变量，within-day r=-0.010，见 Phase 0b 段）+ §4.4 反向因子理论删除 + Phase 1 等权 placeholder 不阻塞（理由：24 天内无已验证横截面信号）+ §5.3/§5.4 Q16-Q17：板块数据来源实测修正（gene_scores 无 industry 列→clist f100 静态映射回填，§5.3 实现路径待实现、tasks 032 前置）+ 板块阶段修饰系数 placeholder 至 60 天回归热替换。

### 14.2 Regime 失效自动检测

不预测 regime，只检测反向因子是否失效：

```
每周盘后计算：
  rolling_30d: 低频次票（freq < 中位数）胜率 vs 高频次票胜率
  
  if 低频次票胜率 < 高频次票胜率（反向因子失效）:
    → 标注"regime 可能切换"
    → 触发因子权重重算（Phase 0b 流程重新跑一次）
    → 不等 kill criteria，提前预警
  
  if 连续 3 周"regime 可能切换":
    → 强制因子权重重算 + 人工审查
```

这是轻量级 regime 检测——不判断市场是什么 regime，只判断"当前因子方向是否还有效"。失效就重算，不等出事。


## 15. 组合级风控

### 15.1 问题定义

当前 PositionAdvisor 只看个股仓位（单票建议仓位 5%），不看组合结构。量化交易的核心风险在组合层面：5 只全在"教育"板块的候选，板块退潮时全军覆没。多策略推荐同一只票不是更高置信度，是相关信号。

### 15.2 板块集中度限制

```
max_per_sector = 2  # 同一板块最多持仓 2 只
```

构建候选池时：按板块分组，每板块最多保留 2 只策略分最高的候选。第 3 只标注"板块集中度超限，建议观察"。

板块归属来源：ZTPoolItem.industry（涨停类）+ concept_blocks（非涨停类）。

### 15.3 总仓位上限

```
max_total_position = 0.30  # 涨停延续策略最多占组合 30%
```

PositionAdvisor 输出的所有候选仓位建议之和不超过 30%。超限时按策略分降序截断——分高的先满，分低的降仓或剔除。

剩余 70% 留给其他策略（价值投资/趋势跟踪/现金）——涨停延续是卫星策略不是核心。


### 15.x 多策略资金分配

30% 总仓位在 9 个策略间分配：

```
kelly_fraction(W, R) = W - (1-W)/R  # W=胜率, R=盈亏比
allocation_strategy = min(kelly_fraction, capacity_constraint, correlation_constraint) * total_capital
```

三个约束取最小值：
- Kelly 公式给出理论上最优比例
- 容量约束：单策略容量 = 候选股日均成交额 x 2% x 持仓数
- 相关性约束：高相关策略共享一个分配池（|r| > 0.7 的策略合并计算容量）

低相关策略可独立分配。高相关策略按合并后的 Kelly 分配。

### 15.4 回撤熔断

```
consecutive_loss_threshold = 3  # 连续 3 笔亏损 → 降仓 50%
drawdown_threshold = 0.08       # 组合回撤 > 8% → 停止开新仓
```

熔断状态持续到下一个盈利交易日（连续亏损打破）或回撤修复到 4% 以内。

熔断日志记录在 `verification_card.db`——可追溯、可审计。

### 15.5 策略去重

同一只票被多个策略推荐时的处理：

```
1. 收集所有策略的候选 → 按 code 分组
2. 同 code 多策略 → 取策略分最高的那个策略的推荐
3. 标注"N 策略推荐"（信息透明但不加仓）
4. 不因为多策略推荐而提高仓位——相关性不是置信度
```

例外：如果推荐的策略分属不同漏斗类型（涨停类 + 非涨停类），说明该票在多个维度都达标，可以标注"多维度共振"但不自动加仓——共振也可能意味着"已经涨完了"。

### 15.6 相关性去重

同板块候选的仓位联动：

```
同板块 2 只候选 → 每只仓位 × 0.8（板块风险叠加）
同板块 3+ 只 → 只保留策略分最高的 2 只，其余剔除
```

这不只是集中度限制，是承认同板块持仓的相关性 > 独立持仓。



### 15.x 账户级硬约束

不是建议，是硬上限——PositionAdvisor 在这些约束内输出仓位：

```
max_concurrent_positions = 5        # 同时持仓不超过 5 只
max_single_position = 0.10         # 单股不超过 10%（即使策略分很高）
max_sector_exposure = 0.20         # 单板块不超过 20%（含相关性暴露）
min_cash_reserve = 0.30            # 永远保留至少 30% 现金
```

涨停延续是卫星策略不是核心——30% 上限 + 30% 现金底线 = 最多 40% 做其他策略或留现金。

### 15.7 策略终止条件（硬性 kill criteria）

不是软告警（§16.6 衰减监控是软的），是自动停机红线：

```
KILL_CRITERIA（任一触发即停机）:
  rolling_30d_win_rate < 45%        # 30 日滚动胜率低于 45%（基准 73% - 28pp）
  rolling_30d_avg_return < -1.0%   # 30 日滚动平均收益为负
  max_drawdown > 15%               # 组合最大回撤超过 15%
  consecutive_loss >= 8            # 连续 8 笔亏损（胜率 73% 下概率 = 0.27^8 = 万分之三）
```

触发后：策略自动停机，进入人工审查。不允许"再观察一下"。
审查通过后恢复交易时，初始仓位降为基准的 50%，连续 5 笔盈利后恢复满仓。

连亏 8 笔在 73% 胜率下统计概率万分之三——如果真的发生了，说明胜率已经不是 73%。

## 16. 执行与成本模型

### 16.1 执行价格模型

当前回测用 close-to-close（T 收盘买入，T+1 收盘卖出），这是理想化执行。实战中：

- **买入价**：T+1 开盘价（涨停股通常跳空高开 3-5%）
- **卖出价**：T+1 盘中最高价（乐观）或 T+1 收盘价（中性）或 T+1 最低价（悲观）

回测框架必须同时输出三种执行场景的收益：

```
return_optimistic  = (next_high - next_open) / next_open * 100   # 买开卖高
return_neutral     = (next_close - next_open) / next_open * 100  # 买开卖收
return_pessimistic = (next_low - next_open) / next_open * 100    # 买开卖低
return_close2close = (next_close - close) / close * 100          # 原口径（对照）
```

决策依据以 `return_neutral`（买开卖收）为主。`return_close2close` 仅作对照——如果 close2close 胜率 73% 但 open2close 只有 60%，说明真实可执行 alpha 比 backtest 显示的小。


#### 订单类型策略

不止市价单一种选择：

```
market_order:   保证成交，不保证价格——开盘波动大时追高 3-5%
limit_order:    限价 = T 收盘 x 1.03——避免追高但可能踏空
conditional:    如"开盘价 < T 收盘 x 1.05 时买入"——折中
```

回测输出三种订单类型的收益对比。如果 limit_order 收益 > market_order（少追高 > 少成交），实战用限价单。

### 16.2 交易成本建模

```
commission_rate = 0.00025   # 佣金 0.025% 单边
stamp_duty = 0.0005         # 印花税 0.05% 卖出单边
slippage = dynamic          # 动态滑点（见下）

round_trip_cost = commission_rate * 2 + stamp_duty + slippage * 2
```

动态滑点模型（按下单量占日成交额比例计算）：

```
slippage = max(0.001, 0.003 * (order_amount / daily_amount))
# 小资金（500万/8亿日成交）→ 0.3% * 0.006 = 0.002% → 取 0.1% 下限
# 中资金（5000万/8亿）→ 0.3% * 0.063 = 0.019% → 取 0.1% 下限
# 大资金（2亿/8亿）→ 0.3% * 0.25 = 0.075% → 取 0.1% 下限
# 超大资金（4亿/8亿）→ 0.3% * 0.5 = 0.15% → 超过下限，实际 0.15%
```

小资金阶段滑点几乎不影响（0.1% 下限主导），但系统内置动态模型，当资金增长时自动反映成本上升。回测时 daily_amount 取候选股最近 20 日平均成交额。

成本参数可配置（backend/config.py），默认值基于 A 股实际费率。回测收益扣减 round_trip_cost 后才是净收益。

### 16.3 跳空风险模型

每日追踪 T+1 开盘 gap 分布：

```
gap_pct = (next_open - close) / close * 100
```

回测输出 gap 统计：
- gap > 5% 的频率（跳空高开吃掉收益）
- gap < -3% 的频率（跳空低开触发止损）
- gap 中位数（正常执行的成本基准）

如果 gap > 5% 的频率 > 30%，说明该策略的回测收益有严重跳空幻觉——大部分收益在开盘时已被吃掉。

### 16.4 市场级熔断

```
market_kill_switch:
  - 上证指数当日跌幅 > 3% → 不开新仓，已有持仓评估减仓
  - 创业板指数当日跌幅 > 4% → 同上（创业板波动更大）
  - 连续 2 日上证跌幅 > 2% → 次日降仓 50%
```

数据源：`astock.index()` 或东财指数 API。盘中每 15 分钟检查一次（与情绪采样同步）。

暴风雨天气 + 指数跌幅 > 3% = 双重熔断，强制清仓。

### 16.5 样本外验证

防止过拟合：

```
1. 数据分拆：前 70% 日期 = train（调因子权重），后 30% = test（验证）
2. train 上调权重 → test 上验证胜率
3. test 胜率与 train 胜率差异 < 10% → 策略稳定
4. 差异 > 10% → 过拟合，回退到等权或用 S047 回测权重
```

当前 74 样本分拆后 train ≈ 52、test ≈ 22。样本量小，但方向性验证比不验证强。

### 16.6 策略衰减监控

每周盘后自动计算各策略的健康度：

```
strategy_health:
  strategy_code: str
  weekly_win_rate: float       # 本周胜率
  rolling_4w_win_rate: float   # 4 周滚动胜率
  baseline_win_rate: float     # 上线时基准胜率
  decay_alert: bool            # rolling_4w < baseline * 0.85 → True
  sample_count: int            # 累计样本量
```

`decay_alert = True` 时：策略自动降权 50%，并在盘后页面标注"策略衰减"。

连续 4 周 `decay_alert = True` → 策略停用，进入人工审查。

### 16.7 性能归因

每笔交易记录：

```
trade_record:
  date, code, strategy_code, strategy_score
  factor_values: {seal_rate, premium, freq, sector_heat, calendar_factor, ...}
  entry_price: next_open  # 真实买入价
  exit_price: next_close   # 真实卖出价
  gross_return: float
  net_return: float  # 扣成本后

  win: bool
```

每月回归分析：各因子对 `net_return` 的贡献度（标准化 beta）。

输出到盘后页面的"性能归因"面板：
- 哪些因子在贡献正收益
- 哪些因子在拖后腿
- 哪些策略在赚钱、哪些在亏钱


### 16.8 收益分布分析

胜率和平均收益不够——必须看分布形状。

```
distribution_metrics:
  win_rate: float           # 胜率
  avg_return: float        # 平均收益
  median_return: float     # 中位数收益
  skewness: float          # 偏度（负偏 = 捡硬币策略）
  max_single_loss: float   # 最大单笔亏损（%）
  max_single_gain: float   # 最大单笔盈利（%）
  profit_loss_ratio: float # 盈亏比 = avg_win / abs(avg_loss)
  sortino_ratio: float     # 下行风险调整收益
  worst_streak: int        # 最长连续亏损笔数
```

关键判断：
- `skewness < 0`（负偏）= 铁轨前捡硬币，标注"负偏风险"
- `profit_loss_ratio < 1.5` = 盈亏比不足，即使胜率 > 70% 也不值得重仓
- `max_single_loss < -8%` = 存在单日巨亏风险（接近跌停），PositionAdvisor 止损线必须覆盖
- `worst_streak >= 4` = 连续亏损风险，回撤熔断线（§15.4）应触发

A 股涨停限制使盈利有上限（+10%），但跌停同样限制亏损下限（-10%）。不过如果持仓多日（非 T+1 卖出），亏损可以连续累积。分析必须按策略的 `max_hold_days` 对齐。


#### VaR / CVaR

```
VaR_95: 95% 置信下单日最大预期亏损（如 -3.5% = 95% 的日子亏不超过 3.5%）
CVaR_95: 亏损超过 VaR 时的平均亏损（尾部条件期望，如 -5.2%）
```

涨停策略收益分布是负偏的——VaR 低但 CVaR 可能很高。
大多数日子没事，出事时很严重。CVaR 比 max drawdown 更精确地刻画尾部风险。

### 16.9 策略容量估算

alpha 能管多少钱取决于候选股的流动性。

```
capacity_estimate:
  avg_daily_amount: float      # 候选股平均日均成交额（亿）
  max_position_pct: float      # 单股最大仓位占比（默认 5%）
  max_concurrent: int           # 同时持仓数（默认 5）
  acceptable_impact: float      # 可接受市场冲击（默认 2%）
  
  per_stock_capacity = avg_daily_amount * 1e8 * acceptable_impact / 100
  total_capacity = per_stock_capacity * max_concurrent
  
  # 示例：avg_daily_amount=8亿, impact=2%, concurrent=5
  # per_stock = 8e8 * 0.02 = 1600万
  # total = 1600万 * 5 = 8000万
  # 结论：策略容量约 8000 万，超过则滑点侵蚀 alpha
```

输出给用户："本策略建议资金体量 <= X"。超过容量时 PositionAdvisor 自动降仓（每只仓位 × capacity_factor）。

容量每月更新一次（基于最近 20 日候选股平均成交额）。

### 16.10 统计严谨性保障

#### 因子共线性检查

在调因子权重之前，计算因子相关矩阵：

```
correlation_matrix = pearson_corr(all_factors)  # N x N
# 对每对因子 (i, j)：
#   |r| > 0.7 → 标注"高相关"，合并或去重
#   |r| > 0.9 → 标注"冗余"，强制去重
```

PCA 降维：计算因子矩阵的主成分。如果前 2 个主成分解释方差 > 90%，说明 5 个因子实际只有 2 个独立维度——权重调整应基于主成分载荷而非原始因子。

输出到 `docs/factor-correlation-matrix.md`（回测脚本自动生成）。

#### 多重检验校正

所有"已验证"定律必须通过 Bonferroni 校正：

```
adjusted_p = raw_p * number_of_tests
# 如果 adjusted_p < 0.05 → 标注"已验证"
# 如果 raw_p < 0.05 但 adjusted_p >= 0.05 → 标注"待积累"
```

当前检验次数 ≈ 15（量比/成交额/游资/5 因子分位/日历/总分分位）。后续每新增一次回测检验，检验次数 +1，所有历史检验的校正 p 值同步更新。

不通过校正的定律不接入策略分——标注为"观察中"，不参与权重计算。

#### 选择偏差验证

当前样本全部来自 `qualify=1`（总分 >= 50）。"低分=高胜率"可能是门槛截断假象。

验证方法：在 `qualify=0`（总分 < 50）的样本上同样做分位胜率回测。

```
qualify=0 样本 → 五分位胜率
如果 40-50 分组胜率 > 73%（基准）→ "低分=高胜率"是真实规律，门槛可降低
如果 40-50 分组胜率 < 60% → 50 分门槛本身有过滤价值，真正 alpha 在 50 附近
如果 40-50 分组胜率 ≈ 73% → 门槛无影响，低分规律是噪音
```

结论影响策略分阈值设置——是否把 qualify 阈值从 50 降到 40。

#### 极端压力测试

定义 3 个压力场景，计算组合最大损失和预设响应：

| 场景 | 定义 | 组合影响 | 预设响应 |
|---|---|---|---|
| 千股跌停 | 次日所有候选 -10% | -3%（5 只 × 6% × -10%） | 触发回撤熔断，停止开新仓 |
| 流动性枯竭 | 涨停股次日无买盘，止损滑点 3%+ | -4.5%（5 只 × 6% × -15%） | 止损改为限价单（不追价），接受不成交 |
| 连续熔断 | 连续 3 日千股跌停 | -9%（T+1 无法减仓） | 第 1 日即触发"暴风雨"天气熔断，强制清仓 |

压力测试每月跑一次（使用最近 20 日候选股模拟），结果输出到盘后页面的"压力测试"面板。

#### 因子载荷追踪

每月对 `trade_record` 做回归：

```
net_return ~ seal_rate + premium + freq + sector_heat + calendar_factor + ...
```

输出每个因子的标准化 beta（贡献度）。beta 持续 < 0.1 的因子标注"贡献不足"，考虑降权。beta 符号反转的因子标注"方向变了"，触发策略审查。


### 16.11 数据完整性

#### 复权口径

回测必须用前复权(qfq)口径，不能用 raw。raw 数据在除权日会产生 -50% 假跌（10送10），污染次日收益计算。

```
kline_resolver adjust="qfq" → 走百度源（原生前复权）
回测脚本 fetch_klines 时传 adjust="qfq"
```

当前 `/tmp/backtest_vol_v2.py` 用新浪 raw 口径——需要切换到 qfq。如果 qfq 源不可达，标注"复权口径不可用，回测结果可能有除权污染"。

#### 除权日检测

即使使用 qfq，也要检测样本区间内的除权事件（防止 qfq 源计算错误）：

```
for each sample:
    check kline for any single-day drop > 15% (likely ex-dividend)
    if found:
        flag as "ex_dividend_suspect"
        exclude from win rate calculation or use qfq return instead
```

数据源：东财 datacenter 的 `RPT_REPORTDATE` 或 mootdx 的 `xdxr`（除权除息）接口。

#### 可成交率统计

涨停股 T+1 可能一字封死无法买入。回测必须输出可成交率：

```
fill_rate = count(next_open < limit_up_price) / total_samples
# next_open = T+1 开盘价
# limit_up_price = T 日涨停价
# 如果 next_open >= limit_up_price → 一字板，买不进
```

实际可执行胜率 = 胜率 × fill_rate + (1 - fill_rate) × 0%（不成交不赚不亏）。

如果 fill_rate 只有 60%，73% 的胜率实际可执行的只有 73% × 60% = 43.8%——这是真实的可执行 alpha。

回测框架输出四列：`close2close_return` / `open2close_return` / `fillable_return`（只算可成交的）/ `fill_rate`。


#### 除权除息日历

持仓期间遇到除权除息：
- 股价"下跌"但持仓不变（qfq 已处理回测，但 live 不一定用 qfq 显示）
- 分红交 20% 红利税（持股 < 1 个月）
- 除权日"跌幅"可能误触发止损

内置除权除息日历（`backend/data/ex_dividend_calendar.json`），候选标注"X 日后除权"。
持仓期间有除权 → 止损线按除权调整后价格计算（不因除权假跌触发止损）。

### 16.12 信号优先级框架

当多层信号冲突时，按优先级仲裁——高层否决低层，不叠加。

```
PRIORITY_HIERARCHY (high → low):
  1. 硬熔断层（市场跌幅 >3% / 暴风雨天气 / 回撤 >8%）
     → 强制：不开仓 / 强制清仓。覆盖一切。
  
  2. 组合风控层（板块集中度超限 / 总仓位超限）
     → 否决：候选剔除 / 仓位截断。不覆盖 #1。
  
  3. 日历因子层（周五 ×0.7 / 节前 ×0.5 / 节前末日 ×0.0）
     → 乘法：仓位建议 × calendar_factor。不否决选股，只调仓。
     → 周四 + 节前冲突时：取更严格的（×0.5 而非 ×1.0）。
  
  4. 策略分层（策略分排序 + qualify 阈值）
     → 主决策：选什么票、排什么序。受 #1-#3 约束。
  
  5. 增强层（板块热度 / 游资席位 / 资讯雷达）
     → 修饰：加分/扣分/标注，不否决 #4 的选股决策。
     → 游资一日游扣分最多 ×0.7，但不否决 #4 选出的票。
```

仲裁规则：
- 同层冲突：取更保守的（min 仓位 / 更严格阈值）
- 跨层冲突：高层否决低层（#1 否决 #4，不是 #1 × #4）
- 输出：每个候选显示"被哪层否决/限制"，透明可追溯

前端候选卡片标注信号来源：
```
[策略分 85] [板块热度 高] [日历 正常] [游资 中风险 ×0.9] [市场 正常]
→ 最终仓位 = 5% × 1.0(日历) × 0.9(游资) = 4.5%
→ 如果市场跌幅 >3% → 覆盖一切，不建仓
```

### 16.13 多持有期回测 + 置信度缩放 + 策略相关性

#### 多持有期回测

不只看 T+1。每个策略按其 max_hold_days 做多周期回测：

```
for horizon in [1, 2, 3, 5, 7]:
    returns_h = [(close[t+horizon] - open[t+1]) / open[t+1] * 100 for each sample]
    win_rate_h = count(returns_h > 0) / n
    avg_return_h = mean(returns_h)
```

输出表格：
```
策略           T+1     T+2     T+3     T+5     T+7
首板挖掘       73%     68%     65%     60%     55%
连板接力       73%     75%     70%     —       —
低吸龙头       73%     72%     76%     80%     78%
平台突破       73%     70%     72%     75%     78%
```

标注每个策略的"最优持有期"——胜率或期望收益最高那个 horizon。

低吸龙头和平台突破的 alpha 可能在 T+3/T+5 才显现——T+1 回测低估了它们。

#### 置信度缩放仓位

PositionAdvisor 按策略分线性缩放：

```
position_pct = base_pct * confidence_factor

confidence_factor = (score - qualify_threshold) / (score_cap - qualify_threshold)
# score=95, threshold=50, cap=100 → factor = 0.9 → position = 5% × 0.9 = 4.5%
# score=70, threshold=50, cap=100 → factor = 0.4 → position = 5% × 0.4 = 2.0%
# score=51, threshold=50, cap=100 → factor = 0.02 → position = 5% × 0.02 = 0.1%
```

score_cap = 策略分上限（不同策略不同，涨停类约 100，非涨停类待定）。

低分票仍可选（过了 qualify 阈值），但仓位极小——不放过边际候选，也不重仓低置信度。

#### 策略间相关性矩阵

每月计算各策略日收益的 Pearson 相关：

```
strategy_returns = {strategy_code: [daily_returns]}
correlation_matrix = pearson_corr(strategy_returns)

# 对每对策略 (i, j)：
#   |r| > 0.7 → "高度相关"，标注"建议合并或择一运行"
#   |r| 0.3-0.7 → "中等相关"，可同时运行但仓位叠加打折
#   |r| < 0.3 → "低相关"，分散有价值
```

4 个涨停类策略候选池可能高度重叠——同一只票被多个策略选中。输出"候选重叠率"：`overlap_rate = 同一股票被 N 个策略选中的比例`。

重叠率高时：不是 9 个策略 = 9 倍 alpha，可能是 3 个独立维度 × 3 个标签。真正有价值的策略是与其他策略低相关的。

输出到盘后页面的"策略相关性"面板。
